# 食品安全预警系统

基于 TypeScript、Express、React/Vite 和 SQLite 的多来源食品安全预警系统。沿用现有账号鉴权、展示页、提醒、任务管理及临时外网分享；覆盖通用食品安全，重点标记调味品。

## Windows 启动

需要 Node.js 24 或以上版本，无需另装数据库。

```powershell
npm.cmd ci
# 首次安装才从模板建立 .env；不要覆盖已有密钥配置。
Copy-Item .env.example .env
npm.cmd run init-admin
npm.cmd run build
npm.cmd start
```

打开 http://127.0.0.1:3000 。首次通过本机初始化命令设置开发者账号，不提供通用默认密码。已有账号及密码保留；普通账号由开发者在后台创建。后续双击 `start.cmd` 即可构建并运行。开发时分别运行 `npm run dev`、`npm run dev:web`，前端开发地址为 http://127.0.0.1:5173 。

密钥仅在服务端 `.env` 设置，后台不回显完整密钥。可通过 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY` 配置模型；每次分析记录模型和提示词版本。定时采集需要电脑与服务持续运行。

## 逐篇采集与模型判断

流程：发现链接 → 读取一篇正文与附件 → 去重 → 立即分析该篇 → 需要预警才将新闻和预警原子写入数据库并发布 → 继续下一篇。不会等全部列表或正文抓完再集中分析。

- 首次采集任务触发时刻之前72小时，固定本次截止时刻。每个来源独立保存首次起点，失败重试不会滑动起点。
- 自动采集统一每24小时运行一次，按上次采集任务开始时间计算下次计划；手动采集后从该次开始时间重新计24小时。断网、停机超过24小时，恢复后只补采一个覆盖缺口的任务；未到期重启不会新增任务，未完成任务恢复时沿用原编号。
- 各来源独立保存成功覆盖截止。采集失败保留缺口，下一次24小时任务再补齐；任务内请求仍有限重试，不会5分钟创建一条自动任务。模型失败重试不改变采集计划。
- 保存来源配置不会立即触发采集或改动下次计划；新增来源在下次自动任务首次覆盖近72小时，已有来源从各自上次成功截止继续。若需立即运行，由用户点击“立即采集”，明确记录为手动采集。
- 模型失败不阻止成功采集边界推进，保留在独立失败暂存区，在失败暂存区逐篇重试。
- 只提供日期的网站按与窗口重叠的自然日保守纳入，避免遗漏边界日稍晚发布的文章；有时分的网站按精确时间判断。重复访问由链接和正文指纹去重。
- URL与正文指纹去重。无需预警文章仅留链接、指纹、判定状态和任务日志，正文及完整模型输出删除；重复报道不再次调用模型，已入库新闻关联多个来源。

每站有独立列表、日期、分页及正文适配。支持HTML表格、xls/xlsx、文本型PDF；附件保留原链接、工作表行号或PDF页行定位。明确标为“合格信息”的大型清单仍下载解析，模型材料保留附件链接及解析行数，不把数千条合格名单填入风险提取上下文；不合格清单完整纳入材料。扫描PDF、过大或无法解析的必要附件进入失败待核查，不凭标题发布。暂不解析Word和图片附件，不将无法获取证据的事件强行发布。

### 判定、分类与发布

模型先决定是否需要预警，再为具体对象分类及提取预警。一篇可以无预警或有多个对象；会议、宣传、全部合格抽检等不自动预警。无预警正文不进入新闻库；模型失败正文只在暂存区。

每个预警对象的 `risks` 数组包含 `category`、`subtype`、`note`，可有多个类别。新闻汇总所有对象的大类标签：生物性（紫）、化学性（橙）、物理性（蓝）、其他风险（灰）。放射性污染按本系统指定口径归入物理性；供应中断、标签欺诈等有明确证据的事件可归其他风险。小类在详情备注显示。

原文证据必须为包含食品名称的连续正文；地区、企业、批次须有逐字依据，不得扩大单批次范围。新闻及附件中的指令不能覆盖系统提示词。结构非法、证据不匹配或分类非法进入失败，支持重试。每次调用90秒超时、最多3次尝试；网页同样设置超时、限速及有限重试。

## 后台与展示

- 新闻库只保留确认需预警的文章，按网站来源、大类和标题筛选；显示原文、附件链接及分析版本。
- 任务中心提供立即采集和进度记录；失败暂存区是模型失败文章的唯一重试入口，逐篇重试，不提供全库分析重置或顶部批量重试。
- 统计口径：新增待判定 = 采集新闻数 − 采集失败数 − 去重数。这里采集新闻数包含已处理成功或失败的新闻，失败数按失败新闻篇数统计，不计入尚未开始处理和窗口外链接；列表页失败无法推算受影响新闻篇数，计入整体采集失败提示及详情，不充当一篇新闻参与公式。新增待判定 = 需预警 + 无需预警已舍弃 + 模型分析失败 + 待处理/处理中。新闻入库按篇、发布预警按对象条数分别计数，一篇可产生多条预警。
- 失败提示统一为“采集失败”和“模型分析失败”。页面、正文、附件和时间识别问题均归入采集失败，按失败位置计“处”；模型分析失败按文章计“篇”。具体原因默认折叠在详情中，内部保留原始诊断记录；后续采集成功后，已恢复的位置不再计入当前失败数。任务明细分页是日志数量，不代表待处理量。
- 普通用户每30秒增量查询；预警详情展示风险分类、证据、原文和附件超链接。阅读与提醒确认分别持久化，多标签页通过服务端事务避免重复提醒；网络恢复后补取。前台支持预警发布时间筛选。

## 数据与升级

数据库默认 `data/food-safety.sqlite`，包含用户、会话、提示词、配置、新闻、来源、分析、预警、读取和提醒、任务、来源检查点、处理暂存及去重记录。密码scrypt加密，会话使用HttpOnly Cookie；所有后台API强制开发者权限。SQLite租约互斥并每30秒续约，只运行一个服务实例。

**迁移版本5是本次明确授权的一次性清库切换**：清理旧新闻、预警、分析、阅读与提醒、任务及采集检查点，保留账号、会话、配置密钥和提示词历史，保存新提示词版本并开始近三天采集。`migrations` 标记保证后续启动不再清库，预警AUTOINCREMENT序号不回退。不要手动删除迁移记录。消息版本变化会让已打开页面清除旧卡片。

迁移版本6仅按新计数公式更新已有任务摘要，不删除新闻或预警，不重新采集、调用模型或改变采集边界。

迁移版本7统一24小时调度计划，保留各来源覆盖检查点和全部业务数据。维护补采及旧版配置触发记录单独注明原因，不冒充定时任务；终态记录只显示一次状态。

新增接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/news?page=&search=&category=&source=` | 已确认预警新闻及分类、来源筛选 |
| `GET /api/admin/failures?page=` | 独立模型失败暂存项 |
| `POST /api/admin/failures/:id/retry` | 按暂存项编号重试单篇 |
| `GET /api/admin/jobs/:id?page=&scope=` | 逐篇日志、分来源进度 |
| `GET/PUT /api/admin/config` | 来源启停及提示词版本 |

原有登录、退出、当前用户、账号管理、预警列表与详情、标记已读、提醒领取、撤下及手动采集接口保留。新闻/预警返回新增分类字段，来源新增`source_name`。

## 临时外网分享及服务器部署

网站启动后双击 `start-share.cmd` 创建Cloudflare临时隧道；把输出的网址和普通用户账号交给朋友。脚本下载固定版本并校验SHA256；`.tools/`保存隧道程序，`.share/`保存网址、进程和日志。电脑、网站和隧道需持续运行。双击`stop-share.cmd`停止分享，本机服务继续运行；再次启动可能得到新网址。可信本机HTTPS代理登录使用Secure Cookie。

Docker部署：

```sh
docker compose build
docker compose run --rm food-safety npm run init-admin
docker compose up -d
```

`food-data`命名卷持久化数据库，反向代理配置HTTPS并保留Host与Origin。仅运行一份服务；不要执行`docker compose down -v`。备份先停服务，再复制完整data目录或数据卷，包含SQLite主文件及可能存在的WAL/SHM。

源码使用现有Git私有仓库，提交后`git push`。`.env`、数据库、采集正文、含密钥文档、`.tools/`及`.share/`不得提交。保留所有Markdown文档；运行还需要node_modules、dist、配置及启动/分享脚本。
