# 食品安全预警系统

食安瞭望持续采集食品安全新闻和抽检公告，逐篇判断是否需要预警。普通用户查看预警和原文，开发者管理采集来源、模型提示词、任务和账号。项目采用 TypeScript、React、Vite、Express 和 SQLite。

## 在 Windows 上运行

安装 Node.js 24 或更高版本。在项目根目录执行：

```powershell
npm.cmd ci
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
npm.cmd run init-admin
npm.cmd run build
npm.cmd start
```

`init-admin` 只在首次设置开发者账号时执行。普通账号由开发者在后台创建。已有环境可双击 `start.cmd` 构建并启动。默认访问 [本机网站](http://127.0.0.1:3000/)。开发时在两个终端分别运行 `npm.cmd run dev` 和 `npm.cmd run dev:web`，然后打开 [Vite 开发页面](http://127.0.0.1:5173/)。

在服务端 `.env` 配置 `MODEL_API_KEY`、`MODEL_BASE_URL` 和 `MODEL_NAME`。后台可测试模型连接并编辑提示词，密钥由服务端读取。将 `SCHEDULER_ENABLED` 设为 `false` 可关闭自动调度。

## 用户页面

首页优先展示近期预警，提供「全部预警」「未读预警」及数量，支持按预警发布时间筛选。日期默认留空，可单独设置起始日或结束日。未读和采集统计在预警动态下方，系统介绍在页面底部。

登录后立即查询，此后每 30 秒检查新增预警，切回页面或网络恢复时也会检查。多条新增合并提醒，阅读状态和提醒确认分别保存，多标签页共用同一账号的提醒记录。

详情以两列表格呈现新闻标题、事件摘要、企业、批次、风险分类、风险因素、影响和关注事项。原文证据及来源链接位于表格下方，可打开公告及附件核对。

## 开发者后台

| 页面 | 功能 |
| --- | --- |
| 任务中心 | 立即采集、查看任务进度和按来源记录的采集窗口，从失败暂存区逐篇重试模型分析 |
| 新闻数据库 | 查看确认需要预警的文章，按风险大类、网站来源或标题筛选 |
| 预警管理 | 按最新排序查看最近最多 300 条预警，每页 15 条，可查看分析和来源、撤下已发布预警 |
| 采集与模型 | 勾选、添加、编辑或删除采集栏目，查看最近采集结果，编辑提示词并测试模型 |
| 账号管理 | 创建账号、重置密码和停用账号 |

在「采集与模型」中勾选需要采集的栏目，点击「保存采集配置」后生效。全部取消勾选会暂停采集。删除栏目会把它移出来源列表，历史新闻和任务记录会保留。采集失败和模型分析失败分别显示，具体原因可在详情中展开。

### 支持的来源

添加栏目时，系统按其网址匹配现有解析规则。全新域名需先在服务端适配列表、分页、日期和正文解析。

| 来源 | 支持范围 |
| --- | --- |
| [食品伙伴网·食品资讯](https://news.foodmate.net/) | 国内、国际及国际预警等资讯栏目 |
| [食品伙伴网·食品安全](https://fsc.foodmate.net/) | 食品安全资讯 |
| [中国食品安全网·食安特报](https://www.cfsn.cn/news/2037.html) | 食安特报及相关子栏目 |
| [中国调味品协会](http://www.chinacondiment.com/) | 新闻和行业动态 |
| [重庆市市场监督管理局](https://scjgj.cq.gov.cn/zt_225/spaqzb/) | 食品安全抽检通告，含綦江区和潼南区的官方抽检栏目 |

## 采集、分析与发布

- 每个来源首次采集覆盖任务触发前 72 小时，截止时刻在任务开始时固定。以后从该来源上次成功覆盖的截止时刻继续。未取得成功覆盖前保留首次窗口起点，各来源的窗口在任务详情中独立记录。
- 自动采集按上一次采集任务的开始时间间隔 24 小时触发。手动采集后重新计算下次时间。停机或断网超过 24 小时后，服务恢复时运行一轮到期任务并覆盖相应缺口。未完成任务恢复时沿用原编号。
- 系统每取得一篇正文就去重并分析。无需预警的文章仅留链接、指纹和处理记录，正文及完整模型输出会清除。需要预警且通过结构、分类与原文证据校验的文章，连同预警在同一事务中写入并发布。一篇新闻可以产生多条预警。
- 支持 HTML 表格、Excel 和文本型 PDF，可保留工作表行号和 PDF 页码。明确标为合格的清单保留附件信息与统计，具体风险分析使用正文及不合格清单。正文缺失、发布时间无法确认或必要附件解析失败时记为采集失败。
- 风险标签分为生物性、化学性、物理性和其他风险。模型必须引用连续的原文证据，涉及地区、企业和批次需有来源支持。模型调用超时为 90 秒，每篇每轮尝试一次。模型失败正文保留在暂存区，可手动重试。

任务统计按「采集新闻 − 采集失败新闻 − 去重 = 新增待判定」计算。列表页读取失败单独计入采集失败提示。新增待判定再分为需预警、无需预警已舍弃、模型分析失败、待处理／处理中。新闻入库按篇计，发布预警按条计。

## 临时外网分享

1. 先运行 `start.cmd`，确认本机网站正常。
2. 双击 `start-share.cmd`，把输出的临时网址和开发者创建的普通用户账号交给朋友。
3. 分享期间保持电脑、网站和隧道运行。双击 `stop-share.cmd` 可关闭隧道，本机网站继续运行。重新创建隧道时网址可能会变。

脚本使用 Cloudflare Tunnel。`.tools/cloudflared.exe` 是隧道程序，`.share/` 保存运行状态、分享网址和启动日志。

## Docker 部署

先准备 `.env`，再执行以下命令。初始化命令只用于首次创建开发者账号。

```sh
docker compose build
docker compose run --rm food-safety npm run init-admin
docker compose up -d
```

Compose 使用 `food-data` 卷持久化 SQLite，默认将容器端口映射到本机回环地址。公开部署时通过 HTTPS 反向代理提供访问，保留原始 Host，使用 `COOKIE_SECURE=true`，只运行一个自动采集实例。需要保留数据库时避免使用 `docker compose down -v`。

## 项目文件与验证

| 路径 | 用途 |
| --- | --- |
| `src/`、`server/` | 用户端、开发者后台、API、采集和模型处理 |
| `data/` | Windows 默认数据库目录，含 SQLite 主文件及可能存在的 WAL、SHM 文件 |
| `.env`、`.env.example` | 本机运行配置和初始化模板 |
| `node_modules/`、`dist/` | Node 依赖及网站生产构建产物 |

| `scripts/windows/`、`.tools/`、`.share/` | 启动与分享脚本、隧道程序及运行状态 |
| `tests/`、`.github/workflows/` | 流程测试和 CI |
| `deploy/Dockerfile`、`compose.yaml` | 镜像构建和服务器部署 |

各文件的用途见 [项目文件夹说明](docs/项目文件夹说明.md)。

数据库默认位于 `data/food-safety.sqlite`。密码使用 scrypt 哈希存储，会话使用 HttpOnly Cookie，后台接口要求开发者权限。迁移随服务初始化执行，既有数据库的历史清理迁移按版本记录只执行一次。备份时先停止服务，再复制整个数据库目录或 Docker 数据卷。

```powershell
npm.cmd test
npm.cmd run check
npm.cmd run build
```

测试使用固定样例和独立数据库，覆盖采集窗口、逐篇发布、去重、证据校验、失败重试、来源管理与鉴权。Git 提交只包含源码、配置模板和说明等项目文件。`.env`、生产数据库、采集正文、隧道程序及运行状态留在本机。
