# 食品安全预警系统

食品伙伴网新闻监测、模型辅助分析与预警展示平台。用户前台展示具体食品风险；开发者后台管理新闻、来源、模型提示词、运行任务和账号。覆盖通用食品安全，重点标记调味品。

## Windows 启动

需要 **Node.js 24 或以上版本**，当前项目使用 Node 内置 SQLite，安装时不需要额外数据库或 Python。

```powershell
npm.cmd ci
Copy-Item .env.example .env
# 编辑 .env，填写 MODEL_API_KEY。不要覆盖已有 .env。
npm.cmd run init-admin
npm.cmd run build
npm.cmd start
```

打开 <http://127.0.0.1:3000>。创建的开发者账号可以访问全部后台；在“账号管理”创建普通用户。前台没有公开注册入口。初始化密码至少 10 位，不提供通用默认密码。已有安装继续使用数据库中保存的账号和已设置的密码；项目不保留明文凭据文件。

后续可双击 `start.cmd`，或者执行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`。脚本检查依赖并构建、启动系统。**定时采集需要进程持续运行**；电脑休眠或关机期间不执行任务，恢复启动后会检查是否到期。首次启动会自动发起采集，运行进度在开发者后台查看。浏览器页面只读取已保存结果，不直接触发模型。

开发时两个终端分别运行 `npm run dev` 和 `npm run dev:web`，访问 <http://127.0.0.1:5173>。

## 模型与配置

`.env.example` 提供阿里云兼容接口与模型名称。密钥只配置在服务端 `.env`，不会写入前端、日志或 Git。可更换 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`。后台“采集与模型”分别保存来源栏目和提示词，互不覆盖未保存内容；提示词版本化，每次分析关联实际使用的版本。

自动采集固定为每 24 小时一轮，不再配置回溯天数、篇数上限或固定翻页上限。首次采集窗口为触发时刻往前 **连续 7 天** 到本次触发时刻（北京时间，包含起点）。例如 10 月 27 日触发，则从 10 月 20 日相同时刻开始。首次失败后保留原来的下限，重试不会让窗口向后滑动而漏掉最早一天。

首次成功后，后续窗口为 **（上一次成功采集截止时刻，本次触发时刻]**。自动运行通常覆盖 24 小时；手动点击则覆盖上次成功截止到本次点击的实际间隔。手动成功采集后，下次自动运行安排在该截止时刻后 24 小时。若关机、长任务或来源失败造成延迟，下一轮会覆盖实际尚未成功采集的时间段，不伪装成固定 24 小时，也不按模型重置或模型重试时间改变采集边界。

资讯首页会进入国内、国际及首页提供的国际预警栏目，食安城市首页会进入其列表页；沿“下一页”遍历，确认列表全部早于窗口下限后停止。按原文发布时间筛选并去重，不递归爬取论坛、商品等无关站点。来源仅允许食品伙伴网域名，重定向同样检查。请求保留间隔、超时、大小限制和最多 3 次重试。首次一周补采和模型分析按顺序处理，后台持续保存进度。

栏目、正文读取失败或时间无法确认时不推进成功截止时刻，下一次覆盖尚未完整采集的窗口；**模型失败不会阻止成功采集边界推进**，失败正文保留供模型单独重试。新装系统会自动开始首次近一周采集；已有安装的数据不会仅因代码升级自动删除。缩短正在执行的首次任务时，必须先停服，再按确认的范围维护任务及数据，之后继续未完成部分。

### 任务中心与统计口径

“任务中心”集中提供立即采集、模型失败重试、模型分析重置和任务运行记录。新闻数据库保留查看正文、单篇重试及前往任务中心入口。普通采集不会重新分析已经成功判定过的重复新闻，也不会自动重试历史模型失败项。

- **采集成功**：本次窗口内成功取得正文的新闻，按规范化原文链接每轮只计一次；已有正文可直接使用。
- **去重**：上述新闻中，链接已存在或正文指纹与已有新闻一致的篇数；同正文的不同来源保留关联。
- **新增 = 采集成功 − 去重**：本次实际新增或补全正文、首次投入模型的新闻篇数。
- 对新增新闻分别统计需要预警、无需预警、模型失败、待处理／处理中；**发布预警条数**独立统计，一篇新闻可能对应多条食品预警。
- 识别的链接数、窗口外新闻、正文失败、列表失败、时间待确认属于明细，不混入上述等式。请求重试不重复计为多篇新闻。

任务支持类型／状态筛选、分页、逐篇结果和错误详情。详情默认显示“本次范围”，排除窗口外扫描日志；可单独切换窗口外日志或全部扫描记录，并显示各范围数量。明细每页 50 条，其页数仅用于展示，不代表待处理数量。窗口外日志用于记录已识别的旧链接和日期，避免反复下载，不投入本次模型分析。采集页队列、文章队列和模型结果持久化，重启续跑同一任务。旧任务标为“旧版记录”，旧 `processed` 只解释为正文请求链接数，不补造成功或去重数量。模型失败重试仅处理 `analysis_failed` 且已有正文的新闻，不抓网页、不清除已有预警、不改变成功采集边界。正文失败仍可在新闻数据库单篇重试。

是否需要预警由模型根据正文判断。所有去重且正文完整的新闻均进入模型分析，不再使用关键词规则预先判定是否相关或值得预警。提示词要求先判断风险是否具体、是否与食品直接关联及是否有原文证据；展会宣传、抽检合格、常识科普、仅行政手续问题等通常无需预警。无需预警时返回 `shouldWarn=false` 和空对象列表，保存原因但不发布消息。调味品只是分类标签，不自动触发预警。

预警对象、原产地、企业及批次均不得凭空推断。模型必须给出包含食品名称的连续原文证据。地区、企业和批次若不为空，须能逐字匹配正文；校验失败保留错误并允许重试。新闻只是材料，不能改变分析指令。一次新闻可发布多个有直接风险证据的食品对象，无风险对象不生成预警。旧内置提示词会通过迁移升级为新版本，自行修改的提示词保留；旧关键词筛除的新闻恢复为待分析，已有分析和预警保留历史记录。

采集状态包括待分析、分析中、已发布、无需预警、已筛除、重复报道、采集失败、分析失败。失败重试不会将已发布的同一新闻再次发布。内容指纹合并重复报道，多个原始链接留在后台供开发者核查。新闻修改和撤稿不自动监测；开发者可撤下不应展示的预警。运行日志区分失败和“没有新增”，不会使用演示新闻填充正式数据库。

### 模型分析重置

开发者在“任务中心”点击“模型分析重置”，可选填新闻发布时间下限（北京时间，包含所选时刻），留空则选择全部正文完整的文章。确认窗口预览将清除的预警数和重新分析的文章数，勾选确认后才执行。这是已有数据库的重新分析，不等于重新采集，不改变采集时间边界。

**重置将删除全部已生成预警，包括所选新闻时间范围外和已撤下的预警，同时删除对应已读记录。** 新闻原文、来源链接及历史分析记录保留；仅对所选范围重新调用模型。没有发布时间的文章仅在不设时间限制时参与，缺正文和重复记录不参与。范围外文章标记“未纳入本次重置”，不会被此次任务送入模型。

任务使用提交时的提示词版本，处理全部入选文章，不受单次采集上限限制，也不重新抓取网页。后台显示处理总数、成功和失败数量，失败可通过新闻行的重试按钮处理。任务队列持久化，服务中断后续跑未完成部分，不重复清空已生成的新结果。前台会在下次轮询时清除旧卡片并加载新预警。已有任务执行中、模型密钥未配置或范围内没有可分析文章时不会执行清除。

## 展示与提醒

前台每 30 秒通过发布序号查询增量，超过一页的新消息分批补取。卡片每 8 秒滚动展示，支持暂停和手动翻页，鼠标悬停、键盘聚焦、查看详情及页面隐藏时暂停，尊重系统减少动画设置。可按预警发布时间选择起止日期，按北京时间包含所选开始日和结束日，支持仅填一端和重置；列表、增量查询、历史加载及分类数量均由服务端按时间范围查询。调味品、未读分类展示已载入内容，顶部待阅读数量保持全局统计。

新增提醒与阅读状态独立持久化。服务器以事务争取提醒，同一用户多个标签页仅有一个获得同一批提醒；离线消息会在下次进入页面时合并提示。提醒被关闭不等于已读，查看预警详情后才标记已读。网络中断时保留最近列表，并在恢复后补取；撤下的预警在下次轮询时移除。

## 架构与数据

- `server/`：Express API、SQLite 迁移、账号与会话、采集器、持久化任务锁、模型分析、定时调度。
- `src/`：React 前台与开发者后台，适配桌面和移动端。

数据库默认位于 `data/food-safety.sqlite`。首次打开自动执行幂等建表迁移，`migrations` 保存版本。包含用户、会话、新闻、来源、任务、分析结果、提示词、预警、已读、提醒游标、配置和任务锁。进程间使用数据库租约互斥，30 秒续约，租约过期后恢复中断状态；仍推荐单服务实例。会话令牌以哈希入库，密码使用带随机盐的 scrypt；停用账号、重置或修改密码使会话失效。

主要接口：

| 接口                                                        | 用途                       |
| ----------------------------------------------------------- | -------------------------- |
| `POST /api/login`、`POST /api/logout`、`GET /api/me`        | 登录、退出、会话           |
| `POST /api/password`                                        | 修改密码并注销会话         |
| `GET /api/alerts?after=序号`                                | 增量预警、未读数、更新时间 |
| `GET /api/alerts?before=序号`                               | 加载更早预警               |
| `GET /api/alerts/:id`、`POST /api/alerts/:id/read`          | 详情与已读                 |
| `POST /api/notifications/claim`                             | 原子领取合并提醒           |
| `/api/admin/overview`、`/news`、`/alerts`                   | 新闻、来源、分析与任务记录 |
| `POST /api/admin/collect`、`POST /api/admin/news/:id/retry` | 采集与失败重试             |
| `GET/PUT /api/admin/config`、`POST /api/admin/model/test`   | 采集与模型配置             |
| `GET/POST /api/admin/users`、`PATCH /api/admin/users/:id`   | 创建、停用账号和重置密码   |
| `POST /api/admin/alerts/:id/withdraw`                       | 撤下预警                   |

重置接口：`GET /api/admin/analysis-reset/preview` 预览影响范围；`POST /api/admin/analysis-reset` 需提交 `confirmed:true`，可选 `since` 为带时区的新闻发布时间下限。

任务中心接口：`GET /api/admin/jobs?page=&kind=&status=`、`GET /api/admin/jobs/:id?page=`；`POST /api/admin/retry-failed` 只提交模型失败重试。`PUT /api/admin/config` 可分别提交 `crawler:{sources:[...]}` 或 `prompt`，旧回溯及上限字段不会再保存或生效。

所有 `/api/admin` 接口强制开发者权限。普通用户可在预警详情的“原文链接”查看并打开新闻来源，包括重复报道关联的多个链接；新闻数据库和原始处理日志由开发者后台管理。

## 服务器部署

### 临时分享给朋友

本机网站启动后，双击 `start-share.cmd` 建立 Cloudflare 临时隧道。脚本首次从 Cloudflare 官方 GitHub 发布下载固定版本并校验 SHA256，将隧道程序保存在 `.tools/`，日志、进程信息和当前网址保存在 `.share/`；这些目录不提交 Git，也不进入 Docker 构建。

把输出的 `https://…trycloudflare.com` 链接发给朋友，并提供后台创建的普通用户账号。公网访问仍需网站账号登录；本机 HTTP 登录保持可用，可信本机 HTTPS 代理访问会使用 Secure 会话 Cookie。电脑、网站和隧道进程需要保持运行。双击 `stop-share.cmd` 可停止公网分享，本机网站继续运行；下次重新开启隧道可能得到不同网址。

临时隧道用于体验，不保证固定网址或持续在线。长期使用请按下面的服务器部署方式运行。

### Docker 与 HTTPS

安装 Docker，按 `.env.example` 建立服务器 `.env` 并配置密钥：

```sh
docker compose build
docker compose run --rm food-safety npm run init-admin
docker compose up -d
```

数据库位于 `food-data` 命名卷，不随容器重建丢失。服务默认仅映射服务器 `127.0.0.1:3000`。对外使用 Nginx/Caddy 反向代理并配置 HTTPS；HTTPS 环境将 `COOKIE_SECURE=true`，直连本机 HTTP 时保持 false。代理需保留浏览器 Host 与 Origin，避免跨来源修改请求被拒绝。仅运行一份服务实例，不执行 `docker compose down -v`，以免删除数据库卷。

备份时先停止服务，再复制完整 `data` 目录或 Docker 数据卷，保留 SQLite 主文件及可能存在的 WAL/SHM 文件；恢复后启动服务检查后台记录。依赖锁定在 `package-lock.json`，升级前先备份数据并运行验证。

## GitHub 私有共享仓库

本地 Git 使用 `main` 分支。`.gitignore` 排除 `.env`、含密钥的原始需求文档、数据库、采集数据、凭据与测试产物。不要使用 `git add -f` 提交这些文件。

现有私有仓库已配置为 `origin`。提交代码后可直接推送：

```powershell
git push
```

仓库为 `food-safety-warning-system` **私有仓库**，首次发布辅助脚本已完成用途并清理。需要分享代码时，在 GitHub 仓库 Settings → Collaborators 邀请指定协作者。网站的临时公网访问使用上面的分享脚本，与代码仓库权限分开。
